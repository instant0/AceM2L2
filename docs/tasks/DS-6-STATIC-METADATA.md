# DS-6 — Static metadata feasibility

**Status:** executed 2026-11-16  
**Result:** `docs/DS-6-STATIC-METADATA-RESULT.md`  
**Harness:** `tests/ds6_static_metadata.lua`  
**Depends on:** DS-4P-F2, DS-17.1  
**Blocks:** DS-15 retrieval, DS-17.5 schema

## Why

DS-4P-F2 showed the best hot shape uses:

- numeric hot arrays;
- shared static names keyed by `npcID`;
- a scoped name index only for name-only/missing-static mobs.

That only works if the addon can ship/load trustworthy static metadata. DS-6
must decide whether that is feasible and how large/versioned it is.

## Scope

Minimum fields to evaluate:

- `npcID`;
- `name`;
- `classification`;
- `level`/level range if available;
- map/zone and instance names only if the client does not expose them reliably;
- project/client/interface version.

Do not include player data, drops, quests, or a full content census unless a
feature requires it.

## Questions

1. Source: official client DB2/API, generated Lua, or another authorized source?
2. Licensing/redistribution: what can be shipped, and what must be generated
   locally?
3. Size for 10k / 100k / 350k rows as a Lua table and as generated source.
4. Load cost: parse time, Lua heap, and whether it belongs in the addon or an
   optional companion.
5. Versioning: projectID, interface, build, and schema version.
6. Regeneration/update process and diff size.
7. Missing/renamed NPCs: hot name fallback; never a fake identity.
8. Name-only/ambiguous NPC handling without a global name index.
9. Per-client separation: Forever vs Midnight.
10. Whether names can be resolved from the client instead of shipped metadata.

## Test profiles

- 10k, 100k, 350k synthetic rows;
- name average lengths 12/24/40;
- classification/level fields present/absent;
- missing-name and duplicate-name cases;
- Lua table vs generated source size;
- optional packed/diff format if the Lua source is too large.

Measure:

- generated bytes;
- Lua heap after load;
- parse/load time;
- lookup by `npcID`;
- scoped name-index memory;
- missing-name fallback.

## Acceptance

- A source/licensing decision is recorded.
- Names for known `npcID`s are available from live capture, not a shipped list.
- Missing/ambiguous names fall back safely.
- Size and load cost are measured at 10k/100k/350k.
- Name-cache/locality versioning is defined (no all-name regeneration).
- No copied QuestieDB/ATT/Carbonite data.
- Per-client separation is explicit.
- DS-15/DS-17.5 can proceed.

## Result

Executed 2026-11-16; revised after review. Key outcome: **do not ship a list of
all names**. Metadata is learned live into a per-character registry keyed by
`npc:<id>`/`name:<lower>`; cold blocks store IDs only. Mobs are
zone/instance/grid-localized, so cold history is per-zone/per-instance blocks,
not a global all-mob matrix.

- No public name-by-ID API is assumed; capture remains authoritative.
- Local registry sample: 158 mobs, 0.05 MB; 10k entries 4.11 MB map / 0.43 MB
  packed; 100k 38.25 / 4.32 MB.
- The shipped-name alternative was measured and rejected: 100k names/24 chars
  packed 3.51 MB vs map 10.67 MB; 350k packed 12.80 MB vs map 40.35 MB.
- Missing IDs fall back to `NPC <id>`; ambiguous names stay ambiguous.
- Optional spawn/locality data is scoped by zone/instance/grid and is not
  required for correctness.
- Do not copy QuestieDB/ATT/Carbonite.

Full measurements and the source/licensing decision:
`docs/DS-6-STATIC-METADATA-RESULT.md`.

## Not required

- live client test;
- exact content census;
- final schema;
- UI work;
- a global name index for all static NPCs.
